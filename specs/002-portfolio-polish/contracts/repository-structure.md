**Owner**: spec-02 (Portfolio Polish) | **Status**: STABLE at `v0.3.0-rc1` | **Source ADRs**: ADR-004 | **Spec refs**: FR-016, FR-017

## Purpose

Specify the top-level repository disposition — which directories and files appear at the root, why, and how the README's "Project Structure" section stays accurate against drift.

## Behavioural Guarantees

1. **Drift detection (Gate G1, FR-016)**: The Project Structure block is regenerated and compared against the committed README on every CI run. Drift fails the build.
2. **Per-entry rationale**: Every entry in the table above appears in the README block with a one-line description; entries listed as "removed" do not appear.
3. **Hatch build exclusion**: All non-library entries (`legacy/`, `DATASETS/*.xlsx`, `docs/`, `tests/`, `Speckit-context-prompts/`, `benchmark/`, `examples/`, `LINKEDIN.txt` if retained) MUST be in `tool.hatch.build.exclude` so the wheel stays slim. CI test asserts this.

## Failure Modes

| Scenario | Detector | Outcome |
|---|---|---|
| A new file is added at the root not in the disposition table | `test_structure_drift.py` (orphan detection) | Merge blocked |
| An entry in the README block does not exist on the filesystem | `test_structure_drift.py` | Merge blocked |
| Wheel build includes an excluded directory | `tests/unit/test_library_hygiene.py` (existing) | Merge blocked |

## Test Coverage

- `tests/integration/test_structure_drift.py`:
  - Re-runs `scripts/regenerate_readme.py`; asserts `git diff --exit-code README.md`.
  - Asserts every top-level filesystem entry is accounted for in the disposition table (no orphan entries).
- `tests/unit/test_library_hygiene.py` (existing from spec-01):
  - Asserts wheel build exclusion list contains expected entries.

## Breaking-Change Policy

Changes to the following are breaking and require a major version bump:

- Moving `src/`, `tests/`, `docs/` out of the repository root.
- Renaming `examples/`.

Adding new top-level directories with corresponding disposition-table entries and README block updates is a non-breaking minor change.

Removing or relocating maintainer-internal directories (`legacy/`, `Speckit-context-prompts/`) is a non-breaking minor change because they are not in the wheel and not part of any public API.
