# Contract: Documentation Site

**Owner**: spec-02 (Portfolio Polish) | **Status**: STABLE at `v0.3.0-rc1` | **Source ADRs**: ADR-002, ADR-003

## Purpose

Specify the public documentation site: URL, sections, build process, deploy mechanism, and the registry-driven content guarantees.

## URL

```text
https://bruno-ghiberto.github.io/3D_BIN_PACKING/
```

This is the default GitHub Pages URL for the repository owner / repository name combination. Custom domains are out of scope for spec-02.

## Site Structure

```text
/
├── index                      (Quickstart + project overview — homepage)
├── algorithms/
│   ├── index                  (Algorithm comparison table)
│   ├── bfd                    (Best-Fit Decreasing — prose + complexity + citation)
│   ├── ffd                    (First-Fit Decreasing)
│   └── shelf                  (Shelf-based)
├── visualisation              (Gallery + theme docs + colour palette)
├── configuration              (Full PackerConfig reference)
├── api/                       (mkdocstrings auto-generated API reference)
└── troubleshooting            (Common issues + resolutions)
```

Plus the maintainer-facing pages (linked from the homepage footer):

- `about` — canonical project identity (≤80-word paragraph + tagline)
- `promo/` (optional; not committed if maintainer prefers private)

## Build

```bash
pip install '.[docs]'      # installs mkdocs-material + mkdocstrings
mkdocs build --strict      # builds site/ directory; --strict fails on any warning
```

CI runs `mkdocs build --strict` on every push and on every PR to `main`. A failing build blocks merge (Gate G8).

## Deploy

Triggered automatically on push to `main` via `.github/workflows/docs-deploy.yml` using the GitHub-official `actions/deploy-pages` action.

```yaml
# Sketch — full workflow lives at .github/workflows/docs-deploy.yml
on:
  push:
    branches: [main]
permissions:
  pages: write
  id-token: write
  contents: read
jobs:
  build:
    steps:
      - actions/checkout@<pinned-sha>
      - actions/setup-python@<pinned-sha>
      - pip install '.[docs]'
      - mkdocs build --strict
      - actions/upload-pages-artifact@<pinned-sha>
  deploy:
    needs: build
    steps:
      - actions/deploy-pages@<pinned-sha>
```

One-time maintainer setup (documented in `docs/maintainers.md` § Pages setup):

1. Repo Settings → Pages → Source = **GitHub Actions**.
2. No custom domain.
3. Save.

## Algorithm Page Contract (per ADR-003)

Each `docs/algorithms/<key>.md` MUST:

- Have YAML front-matter with three mandatory fields:
  ```yaml
  ---
  key: bfd                      # MUST be a valid ALGORITHMS registry key
  complexity: "O(n log n)"      # MUST match the registry entry's complexity_class
  citation: "Crainic et al., 2008"
  ---
  ```
- Open with a one-paragraph prose introduction explaining the algorithm's intuition.
- Include a "Complexity" section restating the front-matter value with reasoning.
- Include a "When to use" section identifying typical input characteristics where the algorithm performs well.
- Include a "Reference" section with the literature citation expanded.
- Embed the algorithm's comparison-gallery PNG: `![<key> packing example](../assets/gallery/<key>.png)` (alt text non-empty per FR-036).

The `docs/algorithms/index.md` page renders the same comparison table that appears in the README (generated by `scripts/regenerate_readme.py` — sourced from the registry).

## Behavioural Guarantees

1. **Registry sync (Gate G8, FR-014)**: For every key in `ALGORITHMS`, a corresponding `docs/algorithms/<key>.md` MUST exist with valid front-matter. Drift fails the build.
2. **Build deterministic**: `mkdocs build --strict` exits 0 on green CI and produces the same `site/` directory bytewise given the same source.
3. **Page load (SC-003)**: Homepage cold-load ≤ 3 seconds on 50 Mb/s connection.
4. **WCAG-AA contrast (FR-038, ADR-012)**: Default mkdocs-material contrast preserved; any custom override re-verified.
5. **API reference auto-generated**: `docs/api/index.md` consumes `bin_packer_3d` docstrings via `mkdocstrings`; no manual maintenance.

## Failure Modes

| Scenario | Behaviour | Outcome |
|---|---|---|
| Algorithm registered but no `docs/algorithms/<key>.md` exists | Drift test fails | Merge blocked |
| `docs/algorithms/<key>.md` front-matter `complexity:` ≠ registry | Drift test fails | Merge blocked |
| `mkdocs build --strict` warning (broken link, etc.) | Build exits non-zero | Merge blocked |
| GitHub Pages source not set to "GitHub Actions" | `actions/deploy-pages` job fails | Manual fix required; logs surface the error |

## Test Coverage

- `tests/integration/test_docs_build.py`:
  - `mkdocs build --strict` exits 0.
  - Every `ALGORITHMS` key has a corresponding `docs/algorithms/<key>.md`.
  - Each page's front-matter `key:` is a valid registry key.
  - Each page's front-matter `complexity:` matches the registry entry.

## Breaking-Change Policy

Changes to the following are breaking and require a major version bump:

- Removing top-level sections (Quickstart, Algorithms, API Reference, etc.).
- Changing the algorithm-page URL pattern (e.g., from `/algorithms/bfd/` to `/algos/bfd/`).
- Switching the documentation framework away from mkdocs-material.

Adding new top-level sections, new optional front-matter fields, or new algorithm pages (matching new registry entries) are non-breaking minor changes.

The site URL is stable for the lifetime of the repository at this owner / name combination; a repository rename or transfer is out of scope for this contract.
