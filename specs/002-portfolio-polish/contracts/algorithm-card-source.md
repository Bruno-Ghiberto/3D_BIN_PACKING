# Contract: Algorithm Card Source

**Owner**: spec-02 (Portfolio Polish) | **Status**: STABLE at `v0.3.0-rc1` | **Source ADRs**: ADR-003, ADR-004 | **Spec refs**: FR-004, FR-013, FR-026

## Purpose

Specify the single source of truth for every consumer that asserts something about the project's registered algorithms — and require every such consumer to source from it. This is the Contract-Honesty (Principle I) anchor of the polish phase.

## Source of Truth

**Path**: `src/bin_packer_3d/algorithms/__init__.py`
**Symbol**: `ALGORITHMS: dict[str, type[BasePacker]]`
**Registration pattern**: `@register("key")` decorator on each Packer class.

Each registry entry carries (via `AlgorithmMetadata`):

- `name` (display name; e.g., `"Best-Fit Decreasing (BFD)"`)
- `complexity_class` (e.g., `"O(n log n)"`)
- `description` (one-line prose)
- `citation` (literature reference)
- `typical_use_case` (one-line prose)

These are the canonical fields. Every consumer MUST source from these and never hardcode.

## Consumers (all MUST source from the registry)

### 1. README comparison table

- Generated by `scripts/regenerate_readme.py` between markers `<!-- BEGIN: ALGORITHMS_TABLE -->` and `<!-- END: ALGORITHMS_TABLE -->`.
- Drift detected by `tests/integration/test_readme_drift.py`.

### 2. CLI `bin-packer info` output

- Already registry-driven from spec-01 (FR-003).
- Continues to source from `ALGORITHMS` in spec-02.

### 3. Documentation site algorithm index (`docs/algorithms/index.md`)

- Same generated-section pattern as the README comparison table.
- Drift detected by `tests/integration/test_docs_build.py`.

### 4. Documentation site per-algorithm pages (`docs/algorithms/<key>.md`)

- Each page MUST have YAML front-matter (`key:`, `complexity:`, `citation:`) matching the registry entry.
- Drift detected by `tests/integration/test_docs_build.py` (per ADR-003).

### 5. Demo command (`bin-packer demo`)

- Iterates `ALGORITHMS.keys()` to run every registered algorithm.
- Adds new algorithms automatically with no code change.

### 6. Visualisation gallery (`docs/assets/gallery/<key>.png`)

- One static PNG per registered algorithm.
- Generated by `bin-packer demo` against `examples/headline.csv` (FR-005, comparison-style gallery per the Q4 clarification).
- Drift detected indirectly: the demo command iterates the registry, so missing algorithm = missing PNG → docs build fails on broken image links.

## Behavioural Guarantees

1. **Single source (Principle I)**: Adding a new algorithm requires only a `@register` call. The README table, docs site index, docs page (after the scaffold), CLI `info`, and demo command all incorporate it automatically.
2. **Drift detection (G1)**: Every consumer is checked against the registry at every CI run. Local divergence between commits is blocked at PR time.
3. **Hardcoded list = bug**: Any file in the polish-phase artefact set that lists algorithm names as a literal sequence is a Contract Honesty violation. Code review MUST reject such code.

## Failure Modes

| Scenario | Detector | Outcome |
|---|---|---|
| New algorithm registered, no docs page added | `test_docs_build.py` | Merge blocked |
| Algorithm renamed in registry, README table not regenerated | `test_readme_drift.py` | Merge blocked |
| Algorithm complexity updated in registry, docs page front-matter not updated | `test_docs_build.py` | Merge blocked |
| Demo command's algorithm list hardcoded (regression) | Code review | PR rejected |

## Test Coverage

- `tests/integration/test_readme_drift.py`: re-runs `scripts/regenerate_readme.py`; asserts `git diff --exit-code README.md`.
- `tests/integration/test_docs_build.py`: asserts algorithm-page completeness + front-matter agreement with registry.

## Breaking-Change Policy

Changes to the following are breaking and require a major version bump:

- Renaming the `ALGORITHMS` symbol or moving it from `src/bin_packer_3d/algorithms/__init__.py`.
- Changing the `AlgorithmMetadata` dataclass field names or types.
- Removing the `@register` decorator pattern.

Adding new metadata fields with defaults, adding new algorithms via `@register`, or restructuring the documentation site's algorithm-page template are non-breaking minor changes.
